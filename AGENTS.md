# Working in this repository (humans and AI agents)

This file is the contract for anyone — human or AI coding agent (Claude, Codex,
...) — sending changes to the runtz MCP server. Agents: read this before a PR.

## Repository layout

- `cmd/runtz-mcp/` — entrypoint; stdio and HTTP transports.
- `internal/mcp/` — the minimal JSON-RPC MCP server (stdlib only).
- `internal/runtz/` — config, scan runner (shells out to the CLI) and the
  embedded documentation snapshot in `internal/runtz/docs/`.
- `internal/tools/` — tool/resource registration.
- `helm/runtz-mcp/` — chart for the hosted server; `helm/environments/` overlays.

The platform lives in [runtz-dev/runtz](https://github.com/runtz-dev/runtz), the
CLI in [runtz-dev/runtz-cli](https://github.com/runtz-dev/runtz-cli).

## Transports

- **stdio** (default) — launched by a local MCP client; scans are allowed.
- **HTTP** (`RUNTZ_MCP_HTTP=:8080`) — the hosted server at `mcp.runtz.dev`
  (prod) / `mcp-dev.runtz.dev` (dev). It is **docs-only**: scan tools
  are never exposed, because scans need the user's code on the local machine.
  Keep it that way — do not wire scan execution into the HTTP path.

## Branch and release flow

```
feature branch ──▶ dev ──▶ main ──▶ GitHub Release
   (your work)     (dev env)            (prod deploy)
```

Branch off `dev`, open PRs against `dev`. Releases promote to `main`;
publishing a Release builds the image, pushes the chart and deploys prod.

## Checks to run before opening a PR

```bash
go vet ./...
go test ./...
go build ./cmd/runtz-mcp
helm lint helm/runtz-mcp   # if the chart changed
```

## Hard rules

- Never commit secrets, tokens or personal endpoints.
- Keep the HTTP transport docs-only (see above).
- Fill the **Generated by** section of the pull request template; a human
  reviews the full diff and is accountable for it.
